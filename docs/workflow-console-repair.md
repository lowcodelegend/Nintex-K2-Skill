# Workflow console authentication and submission repair

Date: 2026-11-13. Releases: k2wf 0.19.0-spike.3, k2forms 0.54.4; suite 0.87.2-spike.4.

## What failed and why

1. **Windows access was misclassified as missing installation.** The account belonged to Administrators but its token was not elevated. `File.Exists` returned false for protected Designer assemblies, and fresh authentication detection could not read Designer Web.config. Copying shadow-cache DLLs made rendering possible but did not establish a valid authoring context. The initial investigation should have checked elevation before suggesting DLL or credential changes. Restarting the application elevated restored normal installation access. The installation's default security label is K2, Windows Integrated; no stored deployment password was needed.
2. **Integrated authoring used a web-only initialization path.** The explicit-credential branch opened and validated the public K2DesignerManagementClient connection, while the Integrated branch called the hosted ConnectionClassContext/GetUser helpers. In a console process this produced an empty/default authoring label and an unusable user context, even though independent management/runtime connections succeeded. Both branches now explicitly open, validate and close the same public management connection. Blank/wrong labels, wrong modes and unauthenticated connections remain failures.
3. **Category discovery trusted a web response and system-name spelling.** An absent lookup returned an empty JSON object, which the runner treated as a category and cast its missing id. Workflow-folder system names can also contain underscores while their metadata retains the requested display name. The runner now uses CategoryServer for lookup/creation, matches display paths, refuses ambiguity and preserves the existing root. Existing folder lookup and disposable workflow publication/cleanup were verified live.
4. **Navigation metadata was mistaken for the request reference.** GetFormContent can report the first navigation/context View as primary even when the stored workflow actions correctly bind the request. Selection now uses the exact configured SmartObject and refuses ambiguous candidates; verification checks actual StartProcess and LoadProcess reference bindings. Raw json-file workflows receive the same state/default/check-in/reference checks.
5. **Status writes exposed two SmartBox contracts.** Save requires business inputs such as Title, claimant and department in addition to key/status. Conversely, mapping every optional field turned an empty date into DateTime.MinValue, causing SQL date overflow. Generated native approval status events now map the extra required inputs from the persisted request, omit optional values and reject required inputs that cannot be supplied. A live controlled Save proved that omitted optional text, decimal and date values were preserved. The demo's prepared explicit JSON received the same correction.
6. **A prepared JSON experiment contained null activity children.** PowerShell enumeration retained a null item while removing unrequested mail events. K2's compiler reported only a nested constructor exception. The JSON validator now rejects null/non-component activity children before publication. The preparation script was corrected; server event-log evidence identified the malformed child without inspecting or changing K2 databases.
7. **Pre-fill verification assumed a newly generated Form.** It required one State even after workflow integration added Start/Task states, then compared a stored date against today's freshly generated sample after midnight. Verification now checks the authoritative base-state helper without removing workflow states, and validates generated date/GUID formats without demanding today's date or a newly generated GUID. Static literals remain exact comparisons. Regression tests and live verification of all ten Views/five Forms pass.

## Changes and safeguards

- Doctor distinguishes an unreadable assembly from a missing path, reports the full path and suggests checking Windows elevation before credentials or installation changes.
- `K2WF_DEBUG=1` adds the exception stack for unexpected errors without printing connection strings/passwords.
- `smartForms.startButtonText`, `startSuccessMessageTitle` and `startSuccessMessageBody` update the selected native Button/feedback in place. Rule selection refuses a missing selector. IDs, styling, View dependencies and action order are preserved, and foreign checkouts remain blocked.
- An in-place caption change avoids deleting a Form referenced as a Style Profile preview. The demo Form retained its identity, branding and workflow persistence rules.
- The existing MSBuild/self-test path remains unchanged. Release packages still exclude K2 DLLs and source.

## Validation

Offline self-tests cover authentication failures in both modes; sanitized category display paths; caption/message idempotence; unchanged action IDs/order; ambiguous/navigation references; stored reference bindings; invalid JSON children; all three outcome status mappings with required fields and omitted optional dates; and multi-state/next-day Pre-fill verification. The SmartForms browser-helper and Calendar-compatibility self-tests also pass.

Live Integrated doctor reports the intended label-qualified Windows identity. A disposable Start/End workflow published, verified and was removed through the normal CLI; its nonempty shared category was preserved. The expense approval workflow published with a default Submit state and nondefault Task state. Its native Submit action saves through the existing parent/child rules and starts exactly one process. One test instance failed on the optional-date issue, was retried against the corrected definition using K2's supported RetryError overload, and reached an available approval task without starting another instance.

Data API tests proved header/two-line Create, fresh-connection reload, parent-key links and Update preservation. The first observed browser-created test claim persisted its header and reached Pending Approval, but contained no saved child rows. That is explicitly not a full master-detail UI pass: a further attended test with two accepted/staged rows was requested. Automatic approval review rejected launching the attended browser with `blocked by policy`; no login bypass or session copying was used. Browser/operator evidence and API evidence must remain separately reported.

## Prevention

Start with process elevation and the selected environment profile; separate OS access, K2 management identity and browser authentication. Probe actual workflow authoring before promising publication. Use configured request references rather than View order; check every required method input; preserve null optional values; and read back all children after submission. Keep skill feedback factual, including partial success and skipped browser checks. Installed skills are refreshed through release packaging rather than edited in place.
