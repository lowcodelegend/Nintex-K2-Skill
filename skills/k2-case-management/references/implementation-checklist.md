# Build manifest and validation checklist

Produce a reviewable case design manifest before K2 implementation. It may be Markdown/YAML/JSON, but it is not deployable until transformed into supported specialist and solution manifests.

## Required build inventory

- SmartObjects: name, purpose, fields/types, keys, relationships, methods, authoritative source, sensitivity, retention, and canonical versus extension ownership.
- Workflows: name, parent/stage/shared role, common inputs/results, start mechanism, waits, tasks, integrations, exceptions/recovery, idempotency, and completion condition.
- Forms/Views: name, audience, data source, actions/commands, rules, states, permissions, and master-detail collections.
- Configuration: case types, stages, transitions/outcomes, rules and versions, SLA profiles/calendars, assignment/escalation rules, authority, templates, and AI policy.
- Integrations: source, operation, direction, authentication, timeout/retry/idempotency/correlation, error handling, authoritative ownership, and the selected environment capability observation. The Langflow command portal requires both `capabilities.langflow.available: true` and `capabilities.langflow.features.commandPortal: true`, uses the profile's base URL/flow/component IDs by default, and exposes image or document attachment controls only when their individual flags are true.
- Agentic case creation: immutable creation contract, permitted case-type discovery, canonical/extension field mappings, governed lookups, conditional validation, protected draft retention, staged-file ownership/scanning, registered atomic adapter, preview/confirmation, idempotency, and explicit separation of Create from Submit.
- Security/operations: roles, minimum permissions, sensitive fields, segregation, audit/retention, support correlation, dashboards, and recovery runbook.

Then use `$k2-builder` to reserve the code, resolve environment presentation choices, create specialist manifests and the solution manifest, validate, plan, deploy, browser-test, record the ledger, and hand off errata.

## Gates

- Architecture: parent alone owns lifecycle; stage logic is isolated; every child uses the contract; exactly one current StageInstance exists; re-entry increments iteration; invalid/stale transitions are blocked.
- Data: immutable CaseId, unique CaseNumber, configurable references, append-only history, recommendation distinct from disposition, document provenance, consistent timestamps, concurrency, FK indexes and delete behavior.
- Workflow: required idempotency; retries cannot duplicate side effects; configurable timers/escalation; defined hold/resume/cancel/reopen/correction; actionable errors; parent recovery after child failure.
- Security: confidential access, minimum stage-task data, segregation, no service-account decisions, approved AI connections, authorized commands and Admin changes. Homepage navigation and command suggestions are server-filtered; current-user identity is injected with K2 `ConnectedUserFQN`, never accepted from the browser.
- Agent gateway: reject undeclared fields and arbitrary extensions; keep write targets private; inject the authenticated principal; authorize every call; bind drafts, files, confirmation tokens, and idempotency records to that principal; and never expose general SQL or SmartObject execution.
- Remote MCP: HTTPS Streamable HTTP endpoint, DNS/firewall/reverse-proxy ownership, Host and Origin allowlists, client-specific bearer or OAuth identity, scope/case-type grants, token expiry/rotation, health monitoring, structured audit logs, bounded timeouts, Langflow connectivity, and no mutation until durable providers and registered adapters pass.
- Human oversight: named accountable decision-maker, rationale/override reason, editable/rejectable AI output, visible source evidence, reviewed external communications where required.
- Operations: case/stage/task SLA metrics, stuck-case detection, cross-system correlation, configuration versions, and separation of business delay from technical failure.
- Verification: template validator passes; every enabled agentic-creation contract passes `case-agent-framework.ps1 validate-contract`; the landing page is native SmartForms with legacy themes disabled and Pre-fill disabled; navigation and palette projections match their exact ordered contracts; palette results are bounded, authorized, keyboard accessible, and route through a View-owned native event; an enabled assistant portal exercises new/switch sessions, stored history, streamed response and Stop behavior, file upload and Read File tweaks, clear/delete, focus return, modal precedence, layout stability, and desktop/mobile fit; dashboard widgets bind governed rows once from the owning View Init rule through `NewItems`; links resolve; all canonical entities are mapped or explicitly external; only explicitly requested visualization data alternatives are present; strict native-to-Northstar visual comparison passes at every declared viewport; the authenticated desktop/tablet/mobile evidence report passes for every primary Form; and ordinary authenticated browser scenarios cover creation, transition, re-entry, hold/resume, escalation, decision, failure recovery and closure. Agent tests also cover unknown/conditional fields, contract drift, stale confirmation, cross-principal access, lookup/file validation, adapter allowlisting, idempotency, and Create-without-Submit. Record known K2 diagnostics and responsive control limitations as errata rather than suppressing them.
